Auto-post trending news
Automatically finds currently-trending stories and adds them to your Google Sheet as new articles — photo-only (no video ever), with a short original teaser and a clear source credit + link, not a full copy of anyone's article.
Mix per run: mostly General/top stories, more Sports and Entertainment, only a little Politics.
Needs the Apps Script Web App URL set up first (Google Sheet tab) — the latest version of that script (below) is what actually finds and adds the stories.
Want this fully hands-off? Open your sheet → Extensions → Apps Script → on the left, click the clock icon ("Triggers") → Add Trigger → choose function autoPostTrending → Select event source: Time-driven → pick e.g. "Hour timer, every 6 hours" → Save. It'll then keep adding trending stories on its own, with no one needing to click anything.
By default new stories publish immediately. To review each one before it goes live instead, open the Apps Script code below, change TREND_AUTO_PUBLISH=true to false, and redeploy — new trending finds will land as Drafts.
Cross-posting to Instagram & TikTok
Whenever an article goes live — from Compose, from editing a Draft into Published, or from a trending find above — the script automatically builds a banner graphic (photo + headline + category badge, the same style as the manual "Download banner" button) and posts that image to Instagram and/or TikTok, with a caption made of the headline, your configured @mentions, and hashtags pulled from the category and tags.
Duplicate-post fix included: the trending finder now locks itself so a scheduled run and a manual click can't overlap, and checks each story's source link (not just its headline text, which can shift slightly) against everything already in the sheet before adding it.
Where do the Instagram/TikTok tokens go? Deliberately not in a form field on this page — those tokens can post as your accounts, so typing them into a website (even this one) means they'd sit in your browser and this page's traffic. Open the Apps Script code below instead, find the SOCIAL_CONFIG block near the bottom, and paste your credentials directly in the script editor — then redeploy. Leave a platform's enabled as false to skip it.
Both platforms need their own setup before anything will actually post: Instagram needs a Business/Creator account linked to a Facebook Page plus a Meta Developer app approved for content publishing. TikTok needs a Developer app approved for the Content Posting API — until TikTok approves it for production, an unaudited app can only post to your own test account, not publicly. Neither of these approvals is something I can get for you; they're a review process on each platform's side.

Reading the sheet (above) needs nothing extra. To let this admin panel write back to your sheet — new posts, edits, publish/unpublish, delete, trending, and live view/like stats — open your sheet → Extensions → Apps Script → delete any starter code → paste the script below (after picking your own secret key, see next field) → Deploy → New deployment → type "Web app" → Execute as: Me → Who has access: Anyone → Deploy → copy the URL ending in /exec and paste it here.
This is what makes posting authorized instead of open to anyone who finds your URL. Pre-filled to admin@buzamedia to match the SECRET line in the script below — change both together if you ever want a different phrase. Requests without the right key are rejected before they touch your sheet.
This one script handles creating, editing, and deleting posts, pushing aggregate stats, and recording individual view/like events (into a new "PostStats" tab it creates automatically) — all routed by an action field the site sends automatically; you don't need to do anything differently per action. It never asks anyone visiting your site to sign in with Google, and never shows a "Google hasn't verified this app" warning — that screen only ever appears to you, once, the moment you personally authorize the deployment. Because it's "Execute as: Me," it always runs with your permissions, quietly, for every request. Note: browsers can't read an Apps Script Web App's response due to CORS, so the site can't confirm success/failure after sending — double-check the sheet itself, or open Apps Script → Executions to see real error messages (like a rejected secret key or a post ID it couldn't find). Also remember: if you edit the script again later, you must create another new deployment — saving alone does not update the live URL.
How it works: the sheet must be shared as "Anyone with the link — Viewer". Once connected, Buza Media reads your sheet's rows as articles every time the site loads (cached briefly in this browser for speed). With the Apps Script URL configured above, editing, publishing/unpublishing, deleting, and adding/removing trending here in the admin panel also writes straight back to the Articles tab — and views/likes/published counts get pushed to the Stats tab automatically. If the Web App URL isn't set, everything still works locally but nothing round-trips to the sheet.
